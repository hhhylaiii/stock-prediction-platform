## 1. 分數與百分位

1. 分數：訊號日 t 上線中的排名 5 日 run 寫在 `prediction` 的 `score`（objective rank、horizon 5，取當天那幾列的 `run_id`）。`in_universe` 也讀同一批列；沒有列就是沒有分數。
2. 百分位：取當天 `in_universe` 為 true 且有分數的列，用 `score` 算 pandas `rank(pct=True)`，同分取平均，最高 1.0。不讀 `prediction.pct`：沒有同分時兩者相同（2026-11-13 實測 976 列，最大差 1.1e-16，沒有同分），同分時 `prediction.pct` 改用 stock_id 排先後。
3. 換 run：上線中的 run 換掉時（例如每月重訓後自動晉升），帳本從當天起讀新 run 的分數，不因為換 run 而再平衡。每一筆動作都記下所用的 `run_id`。
4. 存下的就不改：影子紀錄存下當時用的分數與百分位。之後 `prediction` 的舊日期如果被重寫，已存的名單不改，只記一筆 warning。

## 2. 持有規則 H70/N30

1. 起始狀態是現金 1.0、沒有持股。30 個等額位置，每個訊號日檢查一次。
2. 賣出：持股在訊號日 t 的百分位低於 0.70，或當天不在 universe，或沒有分數。百分位剛好 0.70 的留下。每個訊號日都重新判斷；之前賣不掉的，如果當天已經不符合賣出條件，就繼續持有。這一條只在當天還有其他分數時適用，整天沒有預測的情形見第 5 條。
3. 補位：空位數等於 30 減去賣出後仍在帳上的檔數（賣不掉的也佔位）。候選是未持有、百分位 ≥ 0.90、t 的 `untradable_t1` 不是 true、t+1 有成交（第 3 節第 1 條）的股票。依 `score` 由高到低排，同分依 stock_id 遞增，取前「空位數」檔。每檔分到「現金 ÷ 空位數」，買進手續費從這筆錢裡扣。候選不足時剩下的現金留在帳上，不計利息。
4. 留倉的不再平衡，權重隨價格漂移。
5. 整天沒有預測：訊號日沒有任何 `in_universe` 為 true 且有分數的列時（例如當天研究鏈沒跑、品質關卡沒過），不賣也不買，名單記「當天無預測」，持股照常估值。個別持股缺列或缺分數、而當天有其他分數時，才照第 2 條賣。

## 3. 成交、成本與估值

1. 成交價：訊號日 t 的買賣都在 t+1 的還原開盤價成交（`daily_price` 的 open × adj_factor）。某天「有成交」指 `daily_price` 當天有收盤價，而且開盤價大於 0。t+1 開盤先賣後買，賣得的錢在同一個開盤就能用。
2. 估值：每檔部位的價值，每天用同一次讀到的前後兩天還原收盤價之比往前推；成交當天用同一次讀到的還原開盤價與收盤價之比，賣出時用同一次讀到的前一天還原收盤價與當天還原開盤價之比。沒有收盤價時沿用最近一筆（比值是 1）。不存「單位 × 之後讀到的還原價」：還原因子在讀取時重算（`apps/market/adjust.py`），持有期間遇到除權息，舊日期的還原價會整段改變。還原因子事後改變，已記下的日子不回頭改。
3. 成本：買進收成交金額的 0.1425%；賣出收 0.1425% 加證交稅 0.3%。只對實際成交的金額扣，留倉不產生成本。
4. 賣不掉：t+1 沒有成交（例如停牌）就賣不掉，照最後收盤價估值留在帳上，等到有成交的那天才賣。
5. 下市：該賣而賣不掉的持股，在 `stock_master.delist_date` 已到（不晚於當天）之後的下一個交易日，照最後收盤價結算，並扣賣出成本。
6. 研究腳本的結算方式不同：它在「之後再也沒有成交」時就照最後收盤結算，這用到了事後才知道的事。這個方式只用於模擬器和研究輸出對帳；研究期 H70/N30 遇到 5 次（2016-03-11、2016-04-22、2018-05-24、2018-09-18、2021-12-21），holdout 0 次。影子帳本只用第 4、5 條。

## 4. 名單與成交的時序

| 時間 | 這時候已知 | 寫下什麼 |
| --- | --- | --- |
| t+1 早上的研究鏈（開盤前） | t 的行情與 t 的預測 | 規則當天的名單：要賣的持股，以及依序排好的補位候選（列出所有符合百分位 ≥ 0.90 的，含備位）。這時還不知道 t+1 有沒有成交、`untradable_t1` 是什麼 |
| t+2 早上的研究鏈 | t+1 的行情與 t 的 `untradable_t1` | t 的名單在 t+1 開盤的實際成交（照第 2、3 節），以及 t+1 收盤的淨值 |

兩段都只增不改。重跑同一天的結果相同，不重寫。

名單晚於 t+1 開盤才寫入的（包含 H2 第一次執行時從 2026-11-16 起補的那幾天），標成補記，算法不變。帳本以處理該訊號日時資料庫裡的預測為準；已經記成「當天無預測」的訊號日，之後才寫入的預測不回頭改。

## 5. 對照

1. 等權 universe：交易日 d 的報酬，是 d−1 在 universe 內（看 d−1 預測列的 `in_universe`）的股票，還原收盤價 d ÷ d−1 − 1 的平均，不扣成本；前後兩天的還原價取同一次讀到的。收盤價沒有時沿用最近一筆，所以當天沒成交的股票報酬算 0，仍計入平均；d−1 之前從來沒有收盤價的不計。d−1 沒有任何 universe 列時記 0。
2. `TAIEX_TR`：收盤對收盤的日報酬。

## 6. 只記、不改規則的欄位

1. 賣出成交那天是否開盤跌停：開盤價 ≤ 跌停價，跌停價照 `apps/research/pricelimit.py` 的 `limit_down_price` 算。只記次數，不改成交假設，讓影子紀錄和回測用同一套假設。
2. 該賣但賣不掉、留在帳上的天數。

## 7. 候選模型

| 代號 | 內容 |
| --- | --- |
| C0（基準） | 上線中的排名 5 日 LightGBM。2026-11-16 是 `rank-2026-11.lightgbm.h5.f000`（凍結設計：60 個特徵、訓練窗 60 個月、5 bags，見 `apps/research/production.py` 的 `DESIGNS`）。每月重訓後晉升時跟著換 |
| C1 | Ridge 和 LightGBM 5 日分數的排名平均。LightGBM 那一半就是 C0 當天的分數，不另外訓練。Ridge 那一半照 `apps/research/baseline_runs.py` 的排名 Ridge 配方：篩選後的特徵加缺值旗標，label 是 5 日 `fwd_rank_pct`，懲罰項由訓練窗內的交叉驗證選出；訓在和 C0 當天的 run 同一個 production 摺上（同一個 `as_of` 產生的訓練窗）。合成方式：兩個分數各自在當天 universe 內算 `rank(pct=True)`，等權平均（`apps/research/ensemble.py` 的 `rank_average`）。帳本的百分位再用合成後的分數照第 1 節算一次 |
| C2 | 預測 5 日相對大盤報酬的模型。label 是 `fwd_ret_open`（t+1 還原開盤到 t+5 還原收盤）減去 `TAIEX_TR` 收盤(t+5) ÷ 收盤(t) − 1。`TAIEX_TR` 只有收盤價，所以大盤是收盤對收盤、個股是開盤到收盤，兩段窗口差一個隔夜，和機率模型的相對大盤 label（`apps/research/relative_up.py`）同一種做法。其餘照報酬 5 日的凍結設計（`DESIGNS` 的 return：訓練窗 60 個月、不加市場層特徵、Huber 損失、5 bags、seed 0、特徵與 `return-std1109` 相同），訓在和當天上線中報酬 5 日 run 同一個 `as_of` 的 production 摺上。分數就是預測的相對報酬。這個 label 只開放給影子候選使用，正式建模的路徑選不到 |

1. 凍結：候選 artifact 的模型檔 sha256 與訓練窗日期，在它第一個要打分的訊號日的預測寫入之前，存進影子紀錄，就算凍結。
2. 每月重訓：候選跟著所屬 slot 的上線 run 走，C1 跟排名 5 日、C2 跟報酬 5 日。上線 run 換掉以後，用同一套寫死的配方在新 run 的摺上重訓、凍結；新的凍結之前沿用舊的 artifact 打分。不調參、不改特徵。使用者可以在第一個候選凍結之前否決這條政策；否決時照本檔開頭的規則另開文件。
3. 影子預測不寫進 `prediction`，不出現在任何頁面或 API。

## 8. 比較標準

1. 樣本：每個候選從自己第一個 artifact 凍結之後的第一個訊號日起，連續 60 個交易日，不回補凍結前的日子。之後的每月重訓不重設起點。C0 用同一批日子做成對比較。
2. 主指標是每日 rank IC，算法和線上 monitor 相同：取當天 `in_universe` 為 true、`untradable_t1` 為 false、5 日 `fwd_rank_pct` 已知的列，算分數與 `fwd_rank_pct` 的 Spearman 相關（`apps/research/metrics/ic.py` 的 `daily_rank_ic`，少於 30 檔不算）。每日差等於候選 IC 減 C0 IC，只取兩者都有 IC 的日子；報均值和 Newey-West t（lag 5）。
3. 輔指標：用同一套 H70/N30 帳本換上候選分數，和一本同一天從零開始的 C0 帳本比較。不和 2026-11-16 開的那本比，因為兩邊的起始持股不同。報每日扣成本淨報酬差的累積值、均值、Newey-West t（lag 5），以及兩本的換手和成本。
4. C2 另外報：每日 MAE（對它自己的相對大盤 label）減去「永遠預測 0」的 MAE，報均值和 Newey-West t（lag 5）。
5. C0 的 H70/N30 帳本本身（從 2026-11-16 起）照第 9 節的欄位報：每月淨報酬、成本、超額（對等權 universe）、超額的 Newey-West t（lag 5）、`TAIEX_TR`、年化、最大回撤、年換手。
6. 整理時間：C0 帳本在第 60 個訊號日（2027-02-18）的 5 日 label 結算後整理（2027-02-25 收盤後）；各候選在自己第 60 個訊號日的 5 日 label 結算後整理。
7. 結論只整理給使用者，不設自動換模型的門檻。60 天不足以下定論時，照實寫。

## 10. 限制

1. holdout 摺 44–51 那一次已經用掉。要重現數字只限 H70/N30、H90/N30、H90/N100；不跑其他規則，也不跑候選模型。
2. 研究期可以用來和模擬器對帳，也可以做候選模型的研究期比較。
3. 不換線上模型，不 `promote`，不 `release_holdout`。換不換模型由使用者看第 8 節的整理後決定。
4. 頁面和文件的用字是研究平台的規則紀錄，不寫成投資建議。
